# End-to-end security audit — 31 August 2026

## Scope and method

This audit reviewed the checked-out `origin/main` implementation at commit
`58cee559a1180fa0143ba19e7ec13b522bd46219`, including web, API, worker,
persistence, queue, provider integration, storage, containers, repository
configuration, tests and development process. It reviewed issues #40 (upload),
#28 (documentation), #24 (observability), and active overlap with #44, #56,
#57, #59 and #69.

The method combined source/config/test inspection, route-to-repository ownership
tracing, sink searches, Compose/image review, ASVS 5.0.0 Level 2 applicability,
SAMM/SSDF lifecycle review, and attempted repository-supported checks. It was
non-destructive and did not test real provider/user infrastructure.

Limitations:

- This is not a certification or penetration test.
- The orb has a Docker client but no Compose plugin or Docker daemon access, so
  Docker Compose checks and `pnpm audit` could not execute here. No test result
  is claimed. Commands and errors are recorded under verification.
- GitHub reported this as a private repository and did not expose
  `security_and_analysis` settings; secret scanning, push protection, dependency
  graph and private vulnerability reporting could not be confirmed.
- Hosted identity, ingress/TLS, secrets manager, backups, billing and production
  runtime do not exist and are evaluated as future requirements.

## Prioritized findings

No P0 finding was verified. P1 means “must close before the named public hosted
boundary,” not that the current loopback Community deployment is publicly
exploitable.

### SEC-001 — Hosted authentication and session boundary is not implemented

- **Area / priority:** Authentication, authorization / P1 before public hosted
  production.
- **Finding/evidence:** `AppModule` selects Local Play or Community's
  single-installation-owner middleware. There is no multi-user identity,
  registration/recovery, account disable/delete, MFA/passkey decision,
  inactivity timeout, terminate-all, or hosted anti-automation boundary.
- **Threat/impact/likelihood:** Reusing Community/local identity for a public
  multi-user service would enable spoofing or cross-user compromise. Impact is
  high; likelihood is high only if hosting proceeds without the gate.
- **Affected components:** API auth/middleware, web login, sessions, all
  user-owned resources, deployment ingress.
- **Remediation:** Design a trusted hosted identity adapter; opaque server-side
  session lifecycle; Secure/HttpOnly/host-only cookies; CSRF/origin policy;
  recovery/MFA decision; revocation and anti-automation. Keep Community/local
  modes separate and fail closed.
- **Verification:** Real-auth unauthenticated/wrong-owner tests; fixation,
  expiry/revocation/recovery/CSRF/rate-limit cases; ASVS V6–V8 review.
- **Tracking:** #78.

### SEC-002 — Browser response security policy is absent

- **Area / priority:** Web/frontend / P1 before public hosted production.
- **Finding/evidence:** `apps/web/next.config.ts` only disables the powered-by
  header and defines rewrites. No CSP, HSTS, `nosniff`, referrer,
  `frame-ancestors`, authenticated `no-store`, Permissions Policy or tests were
  found. API Swagger is unconditionally exposed.
- **Threat/impact/likelihood:** Missing defense-in-depth raises XSS/clickjacking,
  content-sniffing, URL leakage and cached-PII impact. Current safe rendering
  lowers immediate likelihood; hosted exposure raises it.
- **Affected components:** Next.js responses, API docs, reverse proxy/HTTPS.
- **Remediation:** Derive a deployment-aware CSP from actual Next.js/font/print
  behavior; set and test headers at the authoritative layer; apply no-store to
  authenticated personal data; disable/restrict docs in production.
- **Verification:** Built-container browser/HTTP assertions for representative
  public/authenticated/error/static responses; CSP report-only compatibility
  trial before enforcement.
- **Tracking:** #76.

### SEC-003 — Security and ordinary quality verification are not enforced in CI

- **Area / priority:** Supply chain, verification / P1 before public hosted
  production.
- **Finding/evidence:** `.github/workflows/design-lint.yml` is the only workflow.
  No repository workflow runs tests/build or dependency review, SAST, secret
  scanning or image/config scanning. GitHub security settings could not be
  verified.
- **Threat/impact/likelihood:** Vulnerable dependencies, leaked secrets and
  authorization/config regressions may merge undetected. Impact high;
  likelihood medium as contribution/distribution grows.
- **Affected components:** GitHub, lockfile, Actions, release images.
- **Remediation:** Coordinate with #44; add a separate low-noise security layer:
  native secret/dependency controls where available, CodeQL, Trivy, scheduled
  full scans and vulnerability triage. Generate SBOM at real release time.
- **Verification:** Intentionally failing test fixtures/config in a safe branch;
  least Actions permissions; documented local Compose reproduction; measure
  runtime/noise.
- **Tracking:** #75; merge #44's canonical quality workflow first or coordinate
  workflow files to avoid conflicts.

### SEC-004 — Hosted data-plane and container least privilege is undefined

- **Area / priority:** Database, queue, secrets, containers, backups / P1 before
  public hosted production.
- **Finding/evidence:** Community Compose intentionally uses static internal
  PostgreSQL/Valkey credentials and plaintext transport. API runs migrations;
  API and worker share the database role. Secrets are environment variables.
  There are no hosted backup controls, network/egress policy, resource limits,
  image scan, digest policy, or comprehensive cap/read-only hardening.
- **Threat/impact/likelihood:** A service/container compromise can have a wider
  data/credential blast radius; insecure hosted topology could disclose PII or
  permit availability/cost abuse. Impact high; likelihood deployment-dependent.
- **Affected components:** Compose/deployment, API, worker, PostgreSQL, Valkey,
  private volume, provider credentials, backups.
- **Remediation:** Define hosted topology with separate migration/runtime roles,
  least grants, TLS/service auth, per-service secrets, egress allowlists,
  encrypted/tested backups, resource/global queue limits, runtime hardening and
  image patch policy. Preserve simple loopback Community operation with clearly
  documented exceptions.
- **Verification:** Deployment config tests; role-denial tests; TLS probes;
  restore drill; mount/secret/egress inventory; Trivy; load/backpressure and
  poison-job tests.
- **Tracking:** #77; parser-specific isolation remains #40.

### SEC-005 — Source retention is modelled but deletion execution is incomplete

- **Area / priority:** Personal-data lifecycle / P1 before the promised
  Community retention behavior or hosted production.
- **Finding/evidence:** Entities, retention timestamps, deletion jobs and
  confirmation/discard scheduling exist, but README explicitly lists retention
  workers and source deletion execution as unsupported.
- **Threat/impact/likelihood:** Sources and source-reconstructing artifacts may
  outlive user/operator expectations. High confidentiality/privacy impact;
  likely until lifecycle execution ships.
- **Affected components:** private storage, imports/semantic artifacts,
  deletion jobs, provenance UI, backups.
- **Remediation/verification:** Implement owner-scoped idempotent deletion,
  retries/failure recovery, derived-artifact/provenance behavior and seven-day
  execution tests without deleting structured resumes.
- **Tracking:** existing #57; do not duplicate it. Backup deletion semantics are
  part of SEC-004.

### SEC-006 — Hostile upload/parser boundary still has open isolation decisions

- **Area / priority:** Upload, parser, AI content / P1 before public hosted
  uploads.
- **Finding/evidence:** Strong structural, expansion, path, process, memory/time,
  temp and prompt-injection controls exist. The worker still mounts private
  storage, holds provider-session access, has network access and runs document
  parsing in the same container boundary; malware/CDR and stronger isolation
  decisions remain open.
- **Threat/impact/likelihood:** A parser exploit could reach broader worker
  capabilities. Impact high; likelihood depends on parser vulnerabilities and
  upload exposure.
- **Affected components:** extraction package, worker image/runtime, private
  storage, provider credentials.
- **Remediation/verification:** Complete #40's threat-based parser isolation,
  scanner/CDR decision, hostile corpus and resource/network tests. Do not add
  keyword blocking or duplicate its implementation here.
- **Tracking:** existing #40.

### SEC-007 — Secret/key lifecycle is not operationalized

- **Area / priority:** Cryptography/secrets / P2.
- **Finding/evidence:** Strong generated secrets and AES-GCM storage exist, but
  encrypted envelopes have one implicit master key, no key ID/rotation path,
  and Compose environment injection; provider disconnect deletes local state
  without an assumed remote revocation endpoint.
- **Threat/impact/likelihood:** Rotation can require downtime/re-encryption and
  leaked refresh tokens may remain provider-valid. Impact medium/high;
  likelihood low in current Community use.
- **Remediation:** Define creation, custody, service access, rotation/refresh,
  revocation and deletion per secret. Add versioned key rotation when hosting
  makes it necessary; document provider revocation limitations.
- **Verification:** old/new key transition, revoked/expired session, service
  secret absence and no-log tests.
- **Tracking:** grouped into #77; revisit with hosted secrets manager/provider
  lifecycle.

### SEC-008 — Runtime security events and protected retention are incomplete

- **Area / priority:** Logging/observability / P2.
- **Finding/evidence:** Privacy-safe import/provider events are mature, but auth
  success/failure, authorization denials, configuration guard failures,
  vulnerability/image findings, protected storage, retention, alerts and
  escalation are not end-to-end defined.
- **Threat/impact/likelihood:** Abuse or compromise may not be detected or
  investigated. Impact medium; likelihood increases with public exposure.
- **Remediation:** Reuse the closed event vocabulary; add bounded auth/authz and
  security-control events, UTC/time synchronization, access/retention and
  alerting. Never record resume/credential payloads.
- **Verification:** metadata allowlist/sentinel tests, detection exercises and
  access/retention checks.
- **Tracking:** #24 for operational architecture and #59 for privacy-safe
  metrics; do not build a parallel platform.

### SEC-009 — Deployment-wide abuse/backpressure controls are incomplete

- **Area / priority:** Availability/cost/business logic / P2 now; P1 before a
  credit-backed hosted provider launch.
- **Finding/evidence:** Per-owner imports are bounded, but login throttling is
  process-local and there are no global request/provider/export budgets,
  deployment queue capacity, stuck/poison-job response or future entitlement
  invariants.
- **Threat/impact/likelihood:** Distributed requests can exhaust CPU, queue,
  provider budget or credits despite per-owner controls. Medium impact for
  Community; high hosted cost impact.
- **Remediation:** Define independently enforceable per-principal and global
  quotas, provider budgets, retry budgets, backpressure and billing/entitlement
  atomicity when those surfaces exist.
- **Verification:** distributed-limit, retry-amplification, duplicate/poison,
  queue saturation and entitlement replay tests.
- **Tracking:** global runtime controls in #77; billing-specific work belongs
  with the future billing issue/product design.

### SEC-010 — Security disclosure intake and release artifact assurance are not ready

- **Area / priority:** Vulnerability management/supply chain / P2 now, P1 before
  public/community distribution.
- **Finding/evidence:** No `SECURITY.md`, verified private reporting channel,
  SBOM, image provenance/signing or vulnerability release automation exists.
- **Threat/impact/likelihood:** Reports may be mishandled and operators may not
  identify affected artifacts. Impact medium; likelihood rises on distribution.
- **Remediation:** Configure a monitored private intake, then add `SECURITY.md`;
  adopt the documented SLA/advisory flow. Generate SBOM and keyless provenance
  when release automation exists; do not invent long-lived signing keys now.
- **Verification:** private-report dry run, advisory/patch drill, release SBOM
  linkage and artifact verification.
- **Tracking:** #75 for tooling; release readiness issue #61 must verify
  disclosure intake before alpha distribution.

## P2/P3 disposition

P2 findings are intentionally grouped above by an owning follow-up or existing
issue rather than expanded into scanner-generated tickets. P3 maturity work
(broader DAST, release signing beyond real distribution, richer dashboards and
higher SAMM maturity) is deferred until production-like auth/release/operations
exist. It must be reconsidered at the documented architecture triggers.
