# Short decision title

Status: Proposed — requires maintainer review

Date: YYYY-MM-DD

Describe the concrete context, what is proposed, and why in one to three
sentences. Link the issue and implementation evidence. Distinguish observed
behavior from a newly proposed decision; if historical rationale is unknown,
say “requires maintainer confirmation” rather than reconstructing it.

## Alternatives and consequences (optional)

Record only meaningful tradeoffs, rejected alternatives, non-obvious costs,
security/privacy implications and conditions that should trigger reconsideration.
Omit this section when the short decision paragraph is sufficient.
